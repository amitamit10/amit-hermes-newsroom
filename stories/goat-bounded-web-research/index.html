GOAT makes web research a set of bounded choices

Seven closed-schema tools route an agent to a specific public-web job—and make retrieval limits visible.

“Search the web” sounds like one action. In practice, it can mean discovery, page extraction, crawling, reachability, metadata lookup, or an answer limited to a handful of snippets. GOAT splits those decisions into separate contracts.

Seven jobs, not one magic endpoint

The public repository describes GOAT as a collection of seven tools. Search returns at most five results; extract fetches one public HTTPS page and caps its text at 8,000 characters; crawl stays on one origin and stops at depth two or ten pages. Probe answers only whether a host is reachable and deliberately returns no page body.[14]

The other three tools narrow the task in different ways. `goat_answer` returns an extractive answer from up to five Wikipedia Action API snippets, not an LLM-written general-web synthesis. Filtered search applies time, domain, or language constraints and excludes results with missing metadata. Vertical search selects one official metadata source, such as Crossref, GDELT, or Wikimedia Commons.[14]

The map above puts those limits beside the tool names. That is the point: “web research” becomes a choice among bounded operations, each with a different evidence shape and a different stopping point.

A smaller result is easier to inspect

The limits are part of the API contract, not merely tuning knobs. A caller can ask for one page instead of a crawl, a reachability probe instead of content, or a citation-bearing extractive answer instead of an open-ended synthesis. The same-origin crawl bound makes its search area visible before it begins.[14]

That does not guarantee a complete answer. A page can be blocked, a metadata field can be absent, and a provider can change. The candidate README describes missing metadata as a reason to exclude a result rather than infer a value. A bounded fetch makes its scope easier to inspect; it does not make the retrieved material true by itself.[14]

Failure behavior is part of the feature

The tools use closed schemas, so an unknown field is not meant to silently become a best-effort request. The README describes predictable errors for blocked URLs, blocked redirects, and missing configuration, with sanitized public error envelopes instead of stack traces or credentials.[14]

There is a nuance worth preserving. The README also discusses a separate provider-challenge error, but the release-candidate notes say that `PROVIDER_BLOCKED` depends on a provider-sibling fix and is not supported by baseline `1311d89a` alone. The honest description is a candidate that documents this gap—not a claim that every failure path is already complete.[14][15]

A router should choose one clear path

Alongside the tools, the repository describes a router that maps task classes to canonical providers. A request for one page can use extraction; a date-filtered discovery request can use filtered search; a scholarly lookup can use a metadata vertical. The goal is to avoid launching every backend just because the task says “research.”[14]

That is a claim about explainability, not truth. One appropriate provider, one explicit contract, and a short source list are easier to inspect than an opaque bundle of simultaneous requests. The evidence still has to be read, compared, and cited by whoever writes the final answer.

Candidate status is part of the story

The README labels this tree a local candidate, and the release-candidate notes identify version 0.2.0. They explicitly say it is not a published release, not a pushed tag, and not an activated live plugin. This article describes the public candidate and its stated design; it does not imply an installation or production deployment.[14][15]

That status is not a footnote. A tool should be evaluated against the code and candidate gates that exist today, not the release label someone hopes to use later. The repository says to verify on a clean second machine before publication or enablement; the next meaningful milestone is reproducibility, not a larger feature list.[14][15]
